# raw-research

글에 사용할 근거를 조사한다. 검색 결과를 나열하거나 블로그 본문을 대신 쓰지 않는다.
최종 산출물은 대상 포스트 폴더의 `search.md` 한 파일이다.

## 1. 대상과 조사 범위 정하기

1. 사용자 요청과 대화에서 대상 포스트의 slug 또는 경로를 찾는다. 경로가 불명확하면 `raw/`의 실제 목록에서 후보를 확인한다. 그래도 특정할 수 없을 때만 묻는다.
2. 대상 `raw/<post-folder>/index.mdx`를 읽고 제목, slug, 본문·목차, 시리즈의 범위를 확인한다. 폴더명과 frontmatter의 slug가 다르면 실제 포스트 폴더에 저장한다.
3. 기존 `search.md`가 있으면 읽고 사용자 메모, 기존 출처, 이미 해결한 질문을 확인한다. 파일이 없다는 이유로 빈 파일부터 만들지 않는다.
4. 다음을 짧게 정리한다.
   - **핵심 질문**: 이 글이 독자에게 답하려는 질문.
   - **포함 범위**: 조사할 개념, 기술 버전, 기간, 적용 조건.
   - **제외 범위**: 인접 주제라도 이번 글에서 다루지 않을 내용.
5. 본문은 조사 범위의 단서이지 사실의 근거가 아니다. 초안에 있는 주장도 같은 기준으로 검증한다. 시리즈의 다른 편까지 조사 범위를 넓히지 않는다.

대상 폴더가 없으면 자동으로 생성하지 않는다. 범위를 정하고 읽기 전용 조사는 할 수 있지만, 저장하려면 먼저 `raw-bootstrap`으로 포스트 폴더를 만드는 별도 승인이 필요하다.

## 2. 웹 자료와 논문 찾기

### 웹 검색

- 핵심 질문별로 한국어·영어 검색어를 만들고 `web_search` 또는 현재 환경의 웹 검색 도구를 사용한다. 원어 용어, 동의어, 버전, 반례·제한 조건을 조합한다.
- 공식 문서, 표준·사양, 원저자의 설명, 대학·공공기관 자료 등 1차 출처를 먼저 찾는다. 해설 글은 이해를 돕거나 원출처를 찾는 데 사용한다.
- 검색 결과의 요약문만으로 사실을 확정하지 않는다. 채택할 URL은 `read` 또는 웹 페이지 읽기 도구로 열어 실제 본문과 해당 절을 확인한다.
- 주제와 직접 관련된 근거가 채워지면 멈춘다. 출처 수를 채우려고 주변 내용을 수집하지 않는다.

### 논문 검색

- 전용 논문 검색 도구가 있으면 사용한다. 없으면 웹 검색의 `site:`와 학술 색인을 사용한다. 분야에 따라 Google Scholar, Crossref, OpenAlex, PubMed, arXiv, 학회·출판사 사이트를 선택한다.
- 핵심 질문의 영어 표현으로 논문을 찾고, 관련 논문의 참고문헌과 후속 연구에서 독립된 근거·반론을 찾는다. 웹 문서 검색만 하고 논문 검색을 했다고 보고하지 않는다.
- 제목, 저자, 연도, DOI 또는 영구 URL을 원출처에서 확인한다. 동료심사 여부, preprint 여부, 정정·철회 공지를 확인할 수 있는 범위에서 확인하고, 확인하지 못한 항목은 `확인 불가`로 남긴다.
- 원문을 읽을 수 있으면 주장에 해당하는 절·쪽·표·그림과 연구 방법, 조건, 한계를 확인한다. 초록만 읽었다면 `초록만 확인`이라고 적고 초록이 뒷받침하는 범위만 사용한다. 유료 본문을 읽은 것처럼 쓰지 않는다.
- 관련 논문을 찾지 못했으면 검색한 색인·검색어와 한계를 기록한다. 논문을 만들거나 관련 없는 논문을 끼워 넣지 않는다.

웹 자료와 논문 모두 발견 당시의 URL, 서지정보, 관련 위치를 기록해 나중에 출처를 잃지 않도록 한다.

## 3. 자료 신뢰성 평가

신뢰도는 **이번에 인용하려는 주장에 대한 근거의 품질**이다. 유명한 사이트, 저자의 직함, 인용 수, 검색 순위만으로 결정하지 않는다. 같은 자료도 주장에 따라 평가가 달라질 수 있다.

### 평가 항목

| 항목 | 높게 평가할 근거 | 낮추거나 보류할 이유 |
|---|---|---|
| 원출처·추적 가능성 | 원문과 작성 주체가 확인되고 인용·데이터가 연결됨 | 원출처 없는 재인용, 존재를 확인할 수 없는 참고문헌 |
| 전문성·책임성 | 해당 분야의 전문성, 책임 주체, 정정 절차가 확인됨 | 전문성 불명, 작성자·기관을 확인할 수 없음 |
| 방법·재현 가능성 | 방법, 표본, 실험 조건, 코드·데이터 또는 계산 과정이 충분히 설명됨 | 비교 조건 은폐, 선택적 사례, 검증 불가능한 수치 |
| 주장과 근거의 적합성 | 자료가 인용하려는 주장과 같은 대상·조건을 직접 다룸 | 상관관계를 인과로 확대, 단일 사례를 일반화, 사양을 실제 성능으로 확대 |
| 검증·한계 공개 | 검토 과정, 독립 검증, 오차·반론·한계가 드러남 | 동료심사만 내세움, 중요한 한계 누락, 철회·정정 내용 미반영 |
| 시점·버전 적합성 | 질문에 맞는 버전과 시점이며 필요한 변경이 반영됨 | 최신 동작을 오래된 문서로 설명, 날짜·버전 불명 |
| 이해관계·목적 | 후원·소속·판매 목적이 공개되고 근거를 별도로 검토할 수 있음 | 홍보성 결론에 독립 근거 없음, 이해관계 은폐 |

오래되었다는 이유만으로 기초 정의나 고전 연구를 낮추지 않는다. 코드·데이터 공개 여부도 분야의 특성과 공개 제약을 고려한다. 이해관계는 자동 탈락 사유가 아니라 추가 검증이 필요한 이유다.

### 판정과 채택 기준

- **높음**: 인용할 주장을 직접 뒷받침하며, 추적 가능한 근거와 적절한 방법·적용 조건이 있고 중대한 결함이 발견되지 않았다. 예: API 요구사항을 설명하는 공식 사양, 방법과 한계가 명확한 체계적 문헌고찰, 충분한 검증 근거를 제시한 연구·기술 문서.
- **보통**: 활용할 근거는 있으나 검증 상태나 일반화 범위에 제한이 있다. 예: 원출처와 재현 방법을 제시한 전문가 해설, 조건이 제한된 단일 연구, 독립 검증이 부족한 preprint. 제한을 함께 인용하고 핵심 주장에는 더 강한 근거를 찾는다.
- **낮음**: 근거가 부실하거나 주장에 비해 방법·조건이 부족하다. 예: 출처 없는 단정, 실험 조건을 숨긴 벤치마크, 증거 없는 제품 우수성 주장, 원문을 확인하지 않은 재인용. 확정된 사실의 근거로 채택하지 않는다.
- **판단 불가**: 원문·작성 주체·방법 등 핵심 정보를 확인하지 못해 품질을 평가할 수 없다. 접근 제한이 있다는 이유만으로 `낮음`이라 단정하지 않는다. 확인된 범위만 기록하고 핵심 근거에서는 보류한다.

이 예시는 출처 유형별 고정 등급이 아니다. 논문·공식 문서는 무조건 높음, 개인 블로그는 무조건 낮음이 아니다. 개인 글도 직접 재현한 실험과 충분한 근거가 있으면 높게 평가할 수 있고, 동료심사 논문도 방법에 결함이 있으면 낮아질 수 있다.

- 체계적 문헌고찰·메타분석은 종합 결론에 적합하지만 검색·선정 방법과 포함 연구의 품질을 확인한다. 단일 연구를 무조건 상위 등급으로 끌어올리지 않는다.
- 공식 문서는 제품의 정의·지원 계약에는 적합하지만, 자사 제품의 성능 우위나 시장 비교를 독립적으로 입증하지는 않는다.
- 철회된 결과는 철회 사유와 관련된 주장의 근거로 채택하지 않는다. 정정본이 있으면 해당 주장을 최신 정정 내용과 대조한다.
- 초록만 확인했다면 평가도 초록에서 확인한 범위로 제한한다. 읽지 않은 방법·데이터의 품질은 `확인 불가`다.
- AI 생성 요약, 검색 요약문, 출처 없는 커뮤니티 글은 원문을 찾는 단서일 뿐, 사실 근거로 채택하지 않는다.
- 등급을 기계적으로 합산하지 않는다. 핵심 방법의 결함을 저자 명성이나 인용 수로 상쇄하지 않는다.

출처별로 **등급, 인용에 사용할 범위, 판단 근거, 한계·이해관계**를 기록한다. 자료 신뢰도와 다음 단계의 주장별 팩트 체크 판정은 별개다. 높은 신뢰도의 자료 하나만 확보했다면 주장은 여전히 `단일 출처`다.

## 4. 크로스체크와 팩트 체크

1. 수집한 내용을 검증 가능한 주장 단위로 나눈다. 정의, 수치, 공식, 인과관계, 지원 여부를 구분한다.
2. 핵심 주장마다 원문 근거를 확인하고, 별도로 작성된 독립 출처와 대조한다. 같은 논문을 소개하는 기사 둘, 같은 문서를 번역·재인용한 글, 같은 데이터셋을 다시 분석한 결과는 독립 검증으로 세지 않는다.
3. 출처가 실제로 같은 주장을 다루는지 확인한다. 서로 다른 버전·대상·측정 조건의 결과를 무조건 일치 또는 모순으로 판정하지 않는다.
4. 다음을 점검한다.
   - **정의·공식**: 기호, 단위, 기준값, 성립 조건. 예: 최대 변위와 peak-to-peak 값, RMS와 최댓값을 혼동하지 않았는가.
   - **수치·비교**: 측정 시점, 표본, 오차, 비교 기준. 벤치마크를 보편적인 성능으로 확대하지 않았는가.
   - **인과관계**: 상관관계나 관찰 결과를 원인으로 단정하지 않았는가.
   - **기술 동작**: 사양의 요구사항, 구현의 관찰 결과, 브라우저·라이브러리 버전 차이를 구분했는가.
   - **연구 결론**: 실험 조건, 한계, 동료심사·정정·철회 상태에 비해 주장이 과장되지 않았는가.
5. 주장별 판정을 다음 중 하나로 기록한다.
   - **교차 확인**: 서로 독립된 출처의 직접 근거가 같은 조건의 주장을 뒷받침한다.
   - **단일 출처**: 직접 근거는 있지만 독립된 근거를 확보하지 못했다. 공식 사양도 이 경우에는 그 권위와 별개로 단일 출처라고 표시한다.
   - **조건부**: 특정 조건에서만 성립한다. 조건과 독립 대조 여부를 함께 적는다.
   - **상충**: 같은 조건에서 출처의 결론이 다르며 해결하지 못했다. 양쪽 근거와 차이를 남긴다.
   - **미확인**: 원문에 접근하지 못했거나 직접 근거가 부족하다.
6. 신뢰도 `높음` 또는 `보통`의 직접 근거로 `교차 확인`한 주장만 확정된 조사 내용으로 정리한다. `조건부`는 적용 조건이 명확하고 독립 대조를 마친 경우에만 포함한다. 나머지는 별도의 주의·추가 확인 영역에 둔다. 추론이나 해석은 사실과 분리해 `해석`으로 표시하고 근거를 붙인다.

다수의 검색 결과가 같은 말을 한다는 이유로 확정하지 않는다. 출처가 충돌하면 최신 자료를 무조건 고르지 말고 버전, 조건, 방법의 차이를 먼저 확인한다.

## 5. 중복 제거와 주제 필터링

- **출처 중복**: DOI, 논문 제목·저자, 원문 URL을 기준으로 동일 자료를 묶는다. 추적 파라미터가 다른 URL, 미러, 번역, 재게시물은 별도 근거로 세지 않는다.
- preprint와 최종 출판본은 하나의 연구로 묶고, 정정까지 반영한 최종본을 우선한다. 버전 간 결론이 다르면 차이를 남기되 독립 출처로 세지 않는다.
- **주장 중복**: 같은 조건의 같은 주장은 한 번만 설명하고 출처를 함께 붙인다. 조건 차이, 반론, 불확실성은 중복으로 삭제하지 않는다.
- **주제 필터**: 각 주장·출처가 핵심 질문에 답하거나 답을 이해하는 데 꼭 필요한지 확인한다. 단순히 관련 키워드가 등장하는 내용은 제외한다.
- 제외한 자료의 장황한 요약은 남기지 않는다. 필요한 경우에만 `동일 연구의 재게시`, `다음 편의 범위` 같은 짧은 제외 이유를 기록한다.
- 기존 사용자 메모는 임의로 지우지 않는다. 중복·범위 밖 메모도 사용자 메모로 구분해 보존하고, 새 조사 내용에서만 중복·범위 필터를 적용한다.

## 6. 출처 기록과 search.md 작성

### 출처 규칙

- 채택한 출처마다 `S01`, `S02`처럼 고유 ID를 부여한다. 갱신할 때는 기존 ID를 유지하고 새 ID를 추가한다.
- 주장과 설명 바로 옆에 `[S01](원문 URL)`을 붙인다. 문서 끝의 출처 목록만으로 어느 주장의 근거인지 추측하게 하지 않는다.
- 웹 출처: 제목, 작성자·기관, 게시·갱신일 또는 `날짜 미상`, URL, 확인한 절, 열람일을 기록한다. 버전이 관련되면 문서·기술 버전도 적는다.
- 논문 출처: 제목, 저자, 연도, 학회·저널 또는 저장소, DOI·영구 URL, 확인한 절·쪽·표·그림, 읽은 범위, 동료심사·preprint·정정 상태를 기록한다. 알 수 없는 값은 추측하지 않는다.
- 근거 위치와 짧은 요지를 남긴다. 검색 결과에서 가져온 제목이나 DOI를 원문 확인 없이 검증된 서지정보로 취급하지 않는다.
- 출처별 신뢰도 등급과 그 이유, 이번 글에서 인용할 수 있는 범위, 한계·이해관계를 기록한다. 같은 출처의 주장별 평가가 다르면 구분해서 적는다.
- 직접 읽지 않은 원출처는 읽은 해설과 구분하고 `재인용·원문 미확인`으로 표시한다. 이 자료로 `교차 확인` 판정을 내리지 않는다.

### 별도 승인 없이 바로 저장

사용자가 `raw-research`의 결과 저장을 상시 승인했다. **조사가 끝나면 대상 포스트 폴더의 `search.md`를 별도 승인 질문 없이 생성·갱신한다.** 이 예외는 해당 자료조사 파일에만 적용하며, `raw/`의 나머지 파일에 대한 승인 규칙은 유지한다.

1. 대상 폴더와 정확한 저장 경로를 확인한 뒤 완성한 조사 결과를 바로 저장한다. 저장 승인 질문을 다시 하지 않는다.
2. 새 파일은 작성하고 기존 파일은 필요한 부분만 수정한다. 기존 사용자 메모와 출처 ID를 보존하며 문서 전체를 무조건 덮어쓰지 않는다.
3. 조사 중 사용자가 파일을 바꿨다면 최신 내용을 읽고 그 변경을 보존한 채 새 조사 내용을 반영한다.
4. `index.mdx`의 본문·frontmatter, 이미지, 다른 포스트, wiki는 수정하지 않는다. 대상 포스트 폴더의 자동 생성과 커밋·푸시도 이 상시 승인에 포함되지 않는다.

### 출력 템플릿

한국어 Markdown으로 작성한다. 아래 구조를 사용하되 실제로 확인한 내용만 채운다. `search.md`에는 post frontmatter를 넣지 않는다. 빈 표나 예시용 자리표시자를 그대로 저장하지 않는다.

```markdown
# 자료조사: <포스트 제목>

## 조사 범위
- 조사일: <YYYY-MM-DD>
- 대상: <실제 포스트 폴더 경로>
- 핵심 질문: <이 글이 답할 질문>
- 포함: <개념·버전·조건>
- 제외: <이번 글에서 다루지 않을 주제>

## 핵심 조사 내용
### <핵심 질문 또는 개념>
- <검증된 설명과 적용 조건>. [S01](<URL>) [S02](<URL>)

## 팩트 체크
| 주장 | 판정 | 근거 | 조건·한계·초안에서 주의할 표현 |
|---|---|---|---|
| <검증할 주장> | <교차 확인 또는 조건부 등> | [S01](<URL>), [S02](<URL>) | <근거 위치·단위·적용 조건> |

## 주의·추가 확인
- <단일 출처·상충·미확인 주장, 사유, 글에서 단정하지 말아야 할 표현과 추가 확인 경로>
- 해당 사항이 없으면 `추가 확인 사항 없음`이라고 적는다.

## 출처
### S01. <자료 제목>
- URL: <원문 URL 또는 DOI 링크>
- 작성자·기관 / 연도·게시일 / 버전: <확인한 정보>
- 자료 유형·검증 상태: <공식 문서·논문·preprint 등과 확인한 상태>
- 신뢰도·판단 근거: <높음·보통·낮음·판단 불가와 구체적 이유>
- 인용 가능 범위·한계·이해관계: <어떤 주장에 쓸 수 있고 어디까지 확인했는가>
- 확인 위치·읽은 범위: <절·쪽·표·그림, 초록만 확인 여부>
- 근거 요지: <어떤 주장을 어느 조건에서 뒷받침하는가>
- 열람일: <YYYY-MM-DD>

## 검색 기록
- 웹 검색: <주요 검색어와 검색한 사이트>
- 논문 검색: <색인·검색어와 결과 또는 찾지 못한 한계>
- 중복·범위 제외: <설명할 필요가 있는 경우에만 짧은 이유>
```

## 완료 확인과 보고

- 웹 검색과 논문 검색을 실제로 수행했는가? 실패·접근 제한·관련 논문 없음은 구분해 기록했는가?
- 모든 핵심 설명에 직접 읽은 출처와 근거 위치가 연결되는가?
- 독립 검증 없는 주장, 조건부 주장, 상충 내용이 확정된 사실과 분리되어 있는가?
- 출처마다 신뢰도와 판단 근거를 기록했으며, 명성·출처 유형만으로 등급을 정하지 않았는가?
- 신뢰도가 낮거나 판단 불가인 자료를 핵심 사실의 근거로 사용하지 않았는가?
- 같은 자료나 같은 주장을 반복하지 않으며 모든 내용이 정한 범위에 속하는가?
- 링크와 출처 ID가 서로 대응하며, 인용한 DOI·서지정보를 실제로 확인했는가?
- 대상 포스트 폴더의 `search.md`만 변경하고 기존 사용자 메모를 보존했는가?

저장 후 정확한 경로, 조사한 핵심 질문, 남은 불확실성을 짧게 보고한다.
